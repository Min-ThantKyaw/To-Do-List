# TaskMaster Backend Guide

This document describes the backend architecture, API endpoints, and data flow for the TaskMaster todo app.

---

## 1. Tech Stack

- **Runtime**: Node.js
- **Framework**: Express.js
- **CORS**: `cors` package
- **Storage**: JSON files (`api/data/`)
- **Module system**: CommonJS (`require` / `module.exports`)

---

## 2. Folder Structure

```
api/
├── app.js                          # Express app setup
├── server.js                       # Server entry point
├── package.json
├── data/
│   ├── tasks.json                  # Task records
│   └── categories.json             # Category records
├── src/
│   ├── controllers/                # Handle HTTP requests and responses
│   │   ├── tasks.controller.js
│   │   └── categories.controller.js
│   ├── models/                     # Read/write JSON files
│   │   ├── task.model.js
│   │   └── category.model.js
│   ├── routes/                     # Define API endpoints
│   │   ├── tasks.routes.js
│   │   └── categories.routes.js
│   ├── services/                   # Business logic and validation
│   │   ├── tasks.service.js
│   │   └── categories.service.js
│   └── middleware/
│       └── errorHandler.js
└── tests/
    └── tasks.test.js
```

### Layer Responsibilities

| Layer | Responsibility |
|-------|----------------|
| **Routes** | Map URLs to controller functions |
| **Controllers** | Parse requests, call services, send JSON responses |
| **Services** | Validate input and apply business rules |
| **Models** | Read and write data to JSON files |
| **Middleware** | Handle errors and cross-cutting concerns |

## 4. API Endpoints

### Tasks

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/tasks` | Get all tasks |
| `GET` | `/api/tasks/:id` | Get one task by ID |
| `POST` | `/api/tasks` | Create a new task |
| `PUT` | `/api/tasks/:id` | Update a task |
| `DELETE` | `/api/tasks/:id` | Delete a task |
| `PATCH` | `/api/tasks/:id/toggle` | Toggle `completed` status |

### Categories

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/categories` | Get all categories |
| `POST` | `/api/categories` | Create a new category |
| `DELETE` | `/api/categories/:id` | Delete a category |

## 5. Request & Response Examples

### Get all tasks

**Request:**

```bash
curl http://localhost:3000/api/tasks
```

**Response:**

```json
{
  "success": true,
  "data": [
    {
      "id": "todo-101",
      "title": "Buy groceries",
      "date": "2026-07-25",
      "priority": "high",
      "category": "Personal",
      "completed": false,
      "createdAt": "2026-07-20T14:30:00.000Z"
    }
  ]
}
```

### Create a task

**Request:**

```bash
curl -X POST http://localhost:3000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Read a book",
    "date": "2026-07-26",
    "priority": "low",
    "category": "Personal"
  }'
```

**Response:**

```json
{
  "success": true,
  "data": {
    "id": "todo-1753101234567",
    "title": "Read a book",
    "date": "2026-07-26",
    "priority": "low",
    "category": "Personal",
    "completed": false,
    "createdAt": "2026-07-21T10:00:00.000Z"
  }
}
```

### Validation error

**Request:**

```bash
curl -X POST http://localhost:3000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": ""}'
```

**Response:**

```json
{
  "success": false,
  "error": "Title, date, priority, and category are required"
}
```

## 6. Data Models

### Task

```json
{
  "id": "todo-101",
  "title": "Buy groceries",
  "date": "2026-07-25",
  "priority": "high",
  "category": "Personal",
  "completed": false,
  "createdAt": "2026-07-20T14:30:00.000Z"
}
```

| Field | Type | Rules |
|-------|------|-------|
| `id` | string | UUID or unique string, generated by backend |
| `title` | string | Required, trimmed |
| `date` | string (YYYY-MM-DD) | Required, cannot be in the past |
| `priority` | string | Required: `low`, `medium`, or `high` |
| `category` | string | Required, must match an existing category |
| `completed` | boolean | Default `false` |
| `createdAt` | string (ISO) | Auto-generated |

### Category

```json
{
  "id": "cat-101",
  "name": "Personal",
  "color": "#22c55e",
  "createdAt": "2026-07-20T14:30:00.000Z"
}
```

| Field | Type | Rules |
|-------|------|-------|
| `id` | string | UUID or unique string |
| `name` | string | Required, unique |
| `color` | string | Optional hex color |
| `createdAt` | string (ISO) | Auto-generated |

## 7. Data Flow Example

Creating a new task:

1. Frontend sends `POST /api/tasks` with JSON body
2. `tasks.routes.js` receives the request
3. `tasks.controller.js` extracts `req.body`
4. `tasks.service.js` validates the data
5. `task.model.js` reads `tasks.json`, adds the new task, writes it back
6. Controller returns the new task as JSON
7. Frontend updates the UI

## 9. Error Handling

All errors flow through the global error handler in `app.js`.

Expected error responses:

| Status | Meaning |
|--------|---------|
| `400` | Bad request / validation failed |
| `404` | Task or category not found |
| `500` | Unexpected server error |

Error response format:

```json
{
  "success": false,
  "error": "Error message here"
}
```

# TaskMaster — Design Document

## 1. Project Overview

A simple, full-stack Todo List application with a clean dashboard UI.

- **Frontend**: Plain HTML, CSS (Tailwind), and vanilla JavaScript
- **Backend**: Node.js + Express
- **Storage**: JSON files on disk (`api/data/`)
- **Goal**: Learn full-stack JavaScript by building real CRUD features with a clean separation between UI, API, and data layers.

---

## 2. High-Level Architecture

```
┌─────────────────┐      HTTP/JSON       ┌─────────────────┐      File I/O       ┌─────────────────┐
│                 │  ──────────────────▶ │                 │ ──────────────────▶ │                 │
│   web (Browser) │                      │   api (Express) │                     │  data/*.json    │
│                 │  ◀────────────────── │                 │ ◀────────────────── │                 │
└─────────────────┘                      └─────────────────┘                     └─────────────────┘
```

### Responsibilities

| Layer | Job |
|-------|-----|
| **Frontend (`web/`)** | Render UI, handle user events, call backend API, manage small UI state |
| **Backend (`api/`)** | Receive HTTP requests, validate input, call services, return JSON responses |
| **Data (`api/data/`)** | Persist tasks and categories as JSON files |

## 4. Data Models

### Task

```json
{
  "id": "uuid-string",
  "title": "Buy groceries",
  "date": "2026-07-25",
  "priority": "high",
  "category": "shopping",
  "completed": false,
  "createdAt": "2026-07-21T10:00:00.000Z"
}
```

| Field | Type | Rules |
|-------|------|-------|
| `id` | string | UUID, generated by backend |
| `title` | string | Required, trimmed |
| `date` | string (YYYY-MM-DD) | Required, cannot be in the past |
| `priority` | string | Required, one of: `low`, `medium`, `high` |
| `category` | string | Required, must match an existing category |
| `completed` | boolean | Default `false` |
| `createdAt` | string (ISO date) | Auto-generated |

### Category

```json
{
  "id": "uuid-string",
  "name": "Work",
  "color": "#3b82f6",
  "createdAt": "2026-07-21T10:00:00.000Z"
}
```

| Field | Type | Rules |
|-------|------|-------|
| `id` | string | UUID, generated by backend |
| `name` | string | Required, unique, trimmed |
| `color` | string | Optional hex color |
| `createdAt` | string (ISO date) | Auto-generated |

## 5. API Design

### Tasks Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/tasks` | Get all tasks |
| `GET` | `/api/tasks/:id` | Get one task by ID |
| `POST` | `/api/tasks` | Create a new task |
| `PUT` | `/api/tasks/:id` | Update a task |
| `DELETE` | `/api/tasks/:id` | Delete a task |
| `PATCH` | `/api/tasks/:id/toggle` | Toggle `completed` status |

### Categories Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/categories` | Get all categories |
| `POST` | `/api/categories` | Create a new category |
| `DELETE` | `/api/categories/:id` | Delete a category |

### Response Format

All API responses use JSON.

**Success example:**

```json
{
  "success": true,
  "data": { ... }
}
```

**Error example:**

```json
{
  "success": false,
  "error": "Title is required"
}
```

## 6. Data Flow Examples

### Creating a Task

1. User fills the modal form and clicks **Save Task**
2. `taskForm.js` validates the input
3. `tasks.api.js` sends `POST /api/tasks` with task data
4. `tasks.routes.js` routes to `tasks.controller.js`
5. `tasks.service.js` validates business rules
6. `task.model.js` reads `tasks.json`, adds the new task, writes back
7. Backend returns the created task
8. Frontend re-renders the task list

### Toggling Complete Status

1. User clicks the checkbox on a task
2. `taskItem.js` detects the click
3. `tasks.api.js` sends `PATCH /api/tasks/:id/toggle`
4. Backend updates `completed` in `tasks.json`
5. Frontend moves the task between pending and completed lists

## 8. State Management

- **Backend state**: Single source of truth in `tasks.json` and `categories.json`
- **Frontend state**: Reload data from backend after every change
- No global state library; each component re-renders when data changes

---

## 9. Validation Rules

### Task Validation

- `title` must not be empty
- `date` must not be empty
- `date` cannot be before today
- `priority` must be `low`, `medium`, or `high`
- `category` must not be empty and must exist in categories

### Category Validation

- `name` must not be empty
- `name` must be unique

---

## 10. Error Handling Strategy

- Validation errors → `400 Bad Request`
- Resource not found → `404 Not Found`
- Unexpected server errors → `500 Internal Server Error`
- All errors go through `errorHandler.js`
- Frontend displays user-friendly messages near the relevant input or as a toast
